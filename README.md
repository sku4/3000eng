# Словарь-минимум с логической структурой — распознанный словарь

Структурированный словарь, распознанный из фотографий книги. Скрипты параметризованы
и пригодны для повторного распознавания новых фото той же книги.

## Файлы

| Файл | Назначение |
|---|---|
| **`dictionary.json`** | итоговый структурированный словарь |
| `run.sh` | master-скрипт: OCR → парсер → сборка (одна команда) |
| `ocr_all.py` | OCR всех JPG (easyocr, ru+en) → `ocr_raw.json` |
| `parse6.py` | парсер: `ocr_raw.json` → `events.json` (записи/заголовки) |
| `build_json.py` | сборщик дерева: `events.json` → `dictionary.json` |
| `canonical_verbs.json` | overlay с чистыми названиями разделов/подразделов (для раздела «Глаголы») |
| `ocr_raw.json` | сырой OCR (координаты, confidence, ink-density) |
| `events.json` | промежуточный список событий |
| `IMG_*.jpg` | исходные фото (страницы 77–99) |

## Быстрый старт (распознать новые фото)

```bash
# 1. положить новые фото в папку, например ./new_photos/
# 2. запустить пайплайн:
./run.sh ./new_photos/ dictionary_new.json
```

При первом запуске `run.sh` сам создаст venv и поставит `easyocr` + `pillow`
(модели easyocr ~100 МБ скачаются при первом OCR). Для раздела «Глаголы» названия
разделов/подразделов автоматически берутся из `canonical_verbs.json`.

### Новые разделы книги (не глаголы)

Overlay `canonical_verbs.json` привязан к разделу «Глаголы». Для других частей
книги (существительные, прилагательные и т.п.) отключите его — названия берутся
из OCR как есть:

```bash
CANONICAL= ./run.sh ./nouns_photos/ dictionary_nouns.json
```

Либо создайте свой overlay по формату `canonical_verbs.json` (`sections[].subsections[].num/ru/en`)
и передайте: `CANONICAL=./canonical_nouns.json ./run.sh ...`.

### Пошагово (без run.sh)

```bash
python3 -m venv venv && venv/bin/pip install easyocr pillow scipy
venv/bin/python ocr_all.py   --input ./new_photos/ --output ocr_raw.json
venv/bin/python parse6.py    --input ocr_raw.json --output events.json --img-dir ./new_photos/
venv/bin/python build_json.py --input events.json  --output dictionary_new.json \
                              --canonical canonical_verbs.json   # опционально
```

### Требования

- Python 3.10–3.14 (тестировалось на 3.14)
- `easyocr`, `pillow`, `scipy` (ставит `run.sh` автоматически)
- Около 500 МБ на диск (torch + easyocr + модели)
- CPU (GPU не требуется; на CPU ~30–40 с на фото)

## Порядок страниц

Порядок фото = порядок страниц. Парсер сортирует по **номеру страницы**, распознанному
OCR (отдельная цифра внизу страницы). Если номер не распознан — fallback по **имени
файла**, поэтому называйте/кладите фото в порядке чтения.

## Структура `dictionary.json`

```jsonc
{
  "book": "Словарь-минимум с логической структурой",
  "theme": { "ru": "Глаголы", "en": "Verbs" },
  "sections": [
    {
      "section": { "ru": "Глаголы стадии", "en": "Verbs of Stage" },
      "subsections": [
        {
          "number": 1,
          "subsection": { "ru": "Начало", "en": "Beginning" },
          "subsection_ocr": { "ru": "...", "en": "..." },
          "entries": [
            { "order": 0, "page": 77,
              "ru": "начинать (ся)", "en": "start",
              "transcription": "[sta:t]", "is_main": true }
          ]
        }
      ]
    }
  ]
}
```

- **тема** — `Глаголы / Verbs`
- **раздел** (9) · **подраздел** (50, нумерация своя внутри раздела) · **запись** (591)
- `order` — сквозной индекс 0…N в порядке чтения (страница, затем сверху-вниз)
- `page` — номер страницы книги
- `is_main: true` — слово выделено **жирным** = главное слово группы. Определяется по
  пикселям: для каждой записи меряется **толщина штриха** (max distance-transform
  бинарной маски) у русского и английского слов, берётся максимум; транскрипция
  **не меряется** (она на фото всегда обычная). Поскольку абсолютная толщина в
  пикселях зависит от снимка (масштаб/кадр), порог **нормируется по странице**:
  `is_main = stroke / median_stroke(page) ≥ 1.30`. Медиана считается по русским
  словам базового (нежирного) текста страницы. Получается ~115 из 591 (≈19%) —
  не «везде true». Порог `1.30` можно менять в `build_json.py` (`BOLD_RATIO`).
- `subsection_ocr` — исходный OCR названия подраздела (до overlay-чистки)

## Метод

1. **easyocr** (`ru`+`en`) по всем фото → `ocr_raw.json` (координаты боксов, confidence, ink-density).
2. `parse6.py`:
   - кластеризует боксы в визуальные строки (разрыв по Y > 20px);
   - классифицирует по колонкам: русское слово (x < 0.20×W), перевод (середина),
     транскрипция (правая колонка / в скобках);
   - восстанавливает записи в плотных регионах (перевод над/под русским словом)
     через pending/trailing-логику: если у текущей записи уже есть перевод — следующая
     строка перевода относится к следующему русскому слову, иначе к текущему;
   - заголовки: тема (`Глаголы/Verbs`), разделы (по ключам `Глаголы/Бытовые/Рабочие`),
     подразделы (по нумерации `N.`/`N`); бегущий колонтитул и титул отсекаются (Y < 0.10×H
     и ключевые слова заголовка).
3. `build_json.py` собирает дерево, накладывает overlay (если задан), нормализует регистр
   русских слов к нижнему, вычисляет `is_main` и добавляет `page`, `order`. Жирность
   считается в `parse6.py` через **толщину штриха** (max distance-transform маски слова;
   меряются ru- и en-боксы, транскрипция нет), в `build_json.py` нормируется по медиане
   страницы (нужен `scipy`).

## Известные ограничения (OCR-шум)

- **Транскрипции** содержат ошибки IPA: `ə`→`э`, `ʃ`→`J`, `ɪ`→`1`/`I`, `ŋ`→`Л`/`n`.
  Транскрипция ориентировочная — основной результат это пары `ru`↔`en`.
- Регистр русских слов нормализован к нижнему (`появляться`, `становиться`, …).
- В плотных регионах на стыке страниц (продолжение подраздела) отдельные записи могут
  быть слияны или с ошибочным переводом.
- Единичные записи содержат мусор (`врезаться в`, `удивлять amaze паwf`) — артефакты OCR.
- `build_json.py` содержит мини-словарь частых OCR-ошибок английского (`EN_FIX`):
  `g0`→`go`, `CrOSS`→`cross`, `tumn`→`turn`, … — пополняйте при необходимости.
