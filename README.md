# Словарь-минимум с логической структурой — распознанный словарь

Структурированный словарь, распознанный из фотографий книги. Скрипты параметризованы
и пригодны для повторного распознавания новых фото той же книги.

## Файлы

| Файл | Назначение |
|---|---|
| **`dictionary.json`** | итоговый словарь (все темы) |
| `run.sh` | master-скрипт: OCR → парсер → сборка (одна тема за запуск) |
| `ocr_all.py` | OCR всех JPG (easyocr, ru+en) → `ocr_raw.json` |
| `parse6.py` | парсер: `ocr_raw.json` → `events.json` (записи/заголовки + жирность) |
| `build_json.py` | сборщик дерева одной темы → dict в схеме `{book, themes}` |
| `merge_dicts.py` | слияние нескольких dict-файлов (тем) в один `dictionary.json` + очистка en + IPA |
| `ipa.py` | генерация корректной IPA-транскрипции из en-слова (CMUdict, брит. RP) |
| `canonical_verbs.json` | overlay чистых названий для темы «Глаголы» (9 разделов) |
| `canonical_adjectives.json` | overlay чистых названий для темы «Прилагательные» (7 разделов) |
| `canonical_nouns.json` | overlay чистых названий для темы «Существительные» (21 раздел) |
| `verbs_dict.json`, `adj_dict.json` | промежуточные dict по темам (входы для merge) |
| `ocr_raw.json` | сырой OCR (координаты, confidence, ink-density) |
| `events.json` | промежуточный список событий |
| `IMG_*.jpg` | исходные фото |

## Быстрый старт (распознать новые фото)

Каждая часть книги (тема) распознаётся отдельно и **добавляется** в общий словарь
через `merge_dicts.py`. Скрипт сам создаст venv и поставит `easyocr` + `pillow`
+ `scipy` (модели easyocr ~100 МБ качаются при первом OCR).

```bash
# 1. собрать новую тему в отдельный dict (с overlay для чистых названий):
CANONICAL=canonical_adjectives.json ./run.sh ./photos/ adj_dict.json
#    для темы без overlay (названия из OCR как есть):
#    CANONICAL= ./run.sh ./photos/ some_dict.json

# 2. слить с уже имеющимся словарём (dictionary.json) в общий:
python merge_dicts.py --inputs dictionary.json adj_dict.json --output dictionary.json
```

При слиянии `order` перенумеруется сквозной по всем темам.

### Пошагово (без run.sh)

```bash
python3 -m venv venv && venv/bin/pip install easyocr pillow scipy
venv/bin/python ocr_all.py    --input ./photos/ --output ocr_raw.json
venv/bin/python parse6.py     --input ocr_raw.json --output events.json --img-dir ./photos/
venv/bin/python build_json.py --input events.json --output adj_dict.json \
                              --canonical canonical_adjectives.json   # опционально
venv/bin/python merge_dicts.py --inputs dictionary.json adj_dict.json --output dictionary.json
```

### Создание overlay для новой темы

Overlay (`canonical_*.json`) содержит чистые названия разделов/подразделов и
поле `theme`, по которому `build_json` привязывает overlay к нужной теме:

```jsonc
{ "theme": {"ru":"Прилагательные","en":"Adjectives"},
  "sections": [
    {"ru":"...","en":"...", "subsections":[{"num":1,"ru":"...","en":"..."}, ...]}
  ]
}
```

Разделы сопоставляются **по порядку** (n-й раздел ↔ n-й в overlay), подразделы —
по **номеру** внутри раздела (нумерация подразделов в книге сбрасывается в каждом
разделе, и `build_json` именно по сбросу определяет границы разделов).

### Требования

- Python 3.10–3.14 (тестировалось на 3.14)
- `easyocr`, `pillow`, `scipy` (ставит `run.sh` автоматически)
- Около 500 МБ на диск (torch + easyocr + модели)
- CPU (GPU не требуется; на CPU ~30–40 с на фото)

## Порядок страниц

Порядок фото = порядок страниц. Парсер сортирует по **номеру страницы**, распознанному
OCR (отдельная цифра внизу страницы). Если номер не распознан — fallback по **имени
файла**, поэтому называйте/кладите фото в порядке чтения.

## Структура `dictionary.json`

```jsonc
{
  "book": "Словарь-минимум с логической структурой",
  "themes": [
    {
      "theme": { "ru": "Глаголы", "en": "Verbs" },
      "sections": [
        {
          "section": { "ru": "Глаголы стадии", "en": "Verbs of Stage" },
          "subsections": [
            {
              "number": 1,
              "subsection": { "ru": "Начало", "en": "Beginning" },
              "entries": [
                { "order": 0, "page": 77,
                  "ru": "начинать (ся)", "en": "start",
                  "tran": "[ˈstɑːt]", "is_main": true }
              ]
            }
          ]
        }
      ]
    },
    { "theme": { "ru": "Прилагательные", "en": "Adjectives" }, "sections": [ ... ] },
    { "theme": { "ru": "Существительные", "en": "Nouns" }, "sections": [ ... ] }
  ]
}
```

- **тема** — часть речи: `Глаголы` (9 разделов, 544 записи), `Прилагательные`
  (7 разделов, 503), `Существительные` (21 раздел, 1781 — распознан полностью, стр. 118–186)
- **раздел** · **подраздел** (нумерация своя внутри раздела, сбрасывается в каждом) · **запись**
- `order` — сквозной индекс 0…N по всему словарю в порядке чтения (темы идут в порядке
  добавления; внутри темы — страница, затем сверху-вниз)
- `page` — номер страницы книги
- `is_main: true` — слово выделено **жирным** = главное слово группы. Определяется по
  пикселям: для каждой записи меряется **толщина штриха** (max distance-transform
  бинарной маски) у русского и английского слов, берётся максимум; транскрипция
  **не меряется** (она на фото всегда обычная). Поскольку абсолютная толщина в
  пикселях зависит от снимка (масштаб/кадр), порог **нормируется по странице**:
  `is_main = stroke / median_stroke(page) ≥ 1.14`. Медиана считается по русским
  словам базового (нежирного) текста страницы. Порог `1.14` можно менять в
  `build_json.py` (`BOLD_RATIO`); проверен на глаголах (стр.77–78: жирные ≥1.14,
  нежирные ≤1.08). (На более раннем скан-наборе использовался 1.30 — разделение
  было шире; на этом наборе фото 77–186 порог понижен до 1.14, чтобы восстановить
  эталон.)

## Метод

1. **easyocr** (`ru`+`en`) по всем фото → `ocr_raw.json` (координаты боксов, confidence, ink-density).
2. `parse6.py`:
   - кластеризует боксы в визуальные строки (разрыв по Y > 20px);
   - **авто-определение колонки записей** на странице (плотнейший cyr-x бин) —
     работает и для глаголов (headwords слева), и для прилагательных (headwords
     слева, но заголовки отцентрированы);
   - **запись = строка с транскрипцией** (ru в колонке записей ИЛИ центрированная
     пара ru+en с транскрипцией — это жирное главное слово группы вроде
     «Цвет/Colour [..]»); транскрипция — только в скобках `[...]`, отдельно
     стоящее латинское слово в правой колонке считается частью перевода, а не
     транскрипцией;
   - **тема** — по ключевым словам (`Прилагательные`/`Существительные`/`Глаголы`);
     **подраздел** — по нумерации `N.`/`N` в начале строки (numbox только для
     крайнего левого токена, чтобы мусорная цифра в заголовке не стала номером);
     заголовки разделов (центрированные, без транскрипции/номера) сбрасывают
     pending, чтобы их en не утечка в следующую запись;
   - восстанавливает записи в плотных регионах (перевод над/под русским словом)
     через pending/trailing-логику;
   - бегущий колонтитул и титул отсекаются (Y < 0.10×H и ключевые слова заголовка).
3. `build_json.py` собирает дерево **по темам**: разделы определяются по **сбросу
   нумерации подразделов** (нумерация в книге сбрасывается в каждом разделе),
   overlay привязывается по имени темы; нормализует регистр русских слов к нижнему,
   вычисляет `is_main`, добавляет `page`, `order`. Жирность считается в `parse6.py`
   через **толщину штриха** (max distance-transform маски слова; меряются ru- и
   en-боксы, транскрипция нет), в `build_json.py` нормируется по медиане страницы.
4. `merge_dicts.py` сливает dict-файлы тем в один, очищает en от OCR-мусора,
   применяет карту ручных исправлений (OVERRIDES/INSERTS/DELETES — сдвинутые
   переводы, потерянные/слипшиеся записи) и перенумерует `order` сквозной.
   Затем генерирует **корректную IPA-транскрипцию** для каждой записи из её en
   через `ipa.py` (CMUdict → брит. RP, неротическое — `start`=[ˈstɑːt],
   `turn`=[ˈtɜːn]), заменяя искажённый OCR-вариант.

## Известные ограничения (OCR-шум)

- **Транскрипция** в `dictionary.json` — сгенерированная IPA (брит. RP,
  неротическое), не OCR: `start`=[ˈstɑːt], `begin`=[bɪˈɡɪn], `warn`=[ˈwɔːn].
  Генерируется из en-перевода в `ipa.py` через CMUdict; слова вне CMUdict
  (британские написания `colourless`, `skilful`, …, гифенованные композиты)
  покрыты fallback-словарём ARPABET и разбиением по дефису.
- Регистр русских слов нормализован к нижнему (`появляться`, `становиться`, …).
- В плотных регионах на стыке страниц (продолжение подраздела) отдельные записи могут
  быть слияны или с ошибочным переводом.
- Английские переводы очищаются от OCR-мусора двумя слоями: `parse6.py` (фильтр
  `is_lat_noise` — не пускает в колонку en фрагменты с цифрами, одиночные буквы,
  смеси регистра вроде `Nn`) и `build_json.py` (`clean_en` — срезает остатки и
  нормализует регистр). Ошибки-слова (напр. `оптимистический`→`sad`, правильно
  `optimistic`) правятся в `EN_FIX`. Регистр en-переводов — нижний.
- `build_json.py` содержит мини-словарь частых OCR-ошибок английского (`EN_FIX`):
  `g0`→`go`, `CrOSS`→`cross`, `tumn`→`turn`, `sad`→`optimistic` (контекстный),
  … — пополняйте при необходимости.
